# 實作與證據

本頁只回答兩件事：AOS 應先用什麼方式試作，以及「測試通過」究竟能證明到哪裡。產品詞義以 [00](00-STATUS-AND-SOURCES.md) 為準；工作台的 JSON、檔名與測試數量都不是公開介面。

## 先把主張切小

一個原型通過，不等於整套 AOS 已成立。每份證據至少要寫清楚：

- 驗的是哪個 Function、哪個狀態轉移或哪個 Linux 邊界。
- 在哪個作業系統、檔案系統與語言版本執行。
- 哪些中斷點真的殺過程式，恢復後比較了什麼。
- 哪些資料只是假的 child 或固定測試資料。
- 明確沒有涵蓋什麼，例如斷電、NFS、多 writer 或網路。

只說「測試全綠」不夠。必須能指出輸入、預期結果、實際留下的檔案，以及可重跑的命令。

## 由 Python 找模型問題

**目前推薦**：先用 Python 做最小、可推翻的語意原型。

Python 適合快速改狀態機、插入中斷點、製造損壞資料，以及比較多套方案。它的任務不是成為最後 Runtime，而是及早發現：

- Call、Task、parent／child 是否分得開。
- 哪一步必須先落盤，哪一步可以重建。
- 結果已知、結果不明與資料矛盾是否被錯誤合併。
- 恢復是否會偷偷重跑可能已有副作用的工作。

原型應一次只換一個抽象。例如先驗一個 leaf process，再驗兩個假 child 的保存順序；不要同時加入 Agent、Git、網路與完整 scheduler，否則失敗時無法知道是哪一層錯。

## 用 C++ 固化 Linux 硬邊界

**目前推薦**：當 Python 已把語意說清楚，再由 C++ 接手會影響正式狀態的部分：

- 建立 process、傳遞 argv 與三條標準串流、等待 exit 或 signal。
- 管理 file descriptor、`CLOEXEC`、signal 與 process tree。
- 做 bounded read、拒絕不合規檔案、處理 lock。
- 依序完成寫檔、`fsync`、rename、目錄 `fsync` 與追加紀錄。
- 重新驗證輸入與證據，最後才提交正式狀態。

C++ 版必須重跑相同測試資料，而不是另寫一套較容易通過的案例。對可攜格式有要求時，Python 與 C++ 應產生逐 byte 相同的結果；不同就先停下來解釋，不用「語意差不多」帶過。

目前 C++ 原型已支持 leaf process 的一小段 Linux 行為，但尚未形成完整 durable writer。尤其「dispatch 前看過某個 executable hash」不等於證明實際啟動的 bytes；檢查與啟動之間仍可能改檔。正式稿不得把這個缺口寫成已解決。

## Janet 先做純規則

**目前推薦**：Janet 先讀 C++ 已驗證、不可修改的狀態快照，只回傳建議；C++ 再依當下版本重新檢查並決定是否提交。

適合交給 Janet 的工作包括排序候選、選擇下一個 child、判斷等待或停止。Janet 第一階段不應取得正式 store 的寫入 handle，也不能自行製造 Receipt。

第一個跨語言接法宜用兩個 process 傳遞有界資料：隔離清楚、可分開殺掉、容易保存輸入輸出。內嵌 Janet、native module 或小型 C ABI 都可後續比較，但跑通其中一案不表示它已成正式 ABI。

目前 Windows 上的 Janet 純規則測試已通過；WSL 尚缺完整 Linux Janet 工具鏈，因此不能宣稱 Linux C++／Janet 內嵌已驗證。

## 證據的五個等級

由弱到強可分成：

1. **想法範例**：幫助理解，沒有可執行驗證。
2. **單一路徑測試**：正常案例能跑，尚未涵蓋損壞與中斷。
3. **反例測試**：非法輸入、競爭與結果不明會被正確擋下。
4. **中斷恢復測試**：在指定落盤點殺掉 writer，重開只得到完整舊狀態、完整新狀態或明確停止。
5. **跨實作比對**：Python、C++，以及適用時的 Janet，對同一固定資料給出相同判定與可攜 bytes。

每頁只能引用實際達到的等級。process-kill 測試不等於斷電；同一台機器的 ext4／WSL 結果不等於 NFS；single writer 不等於多人同寫安全。

## 目前工作台證明的窄範圍

**原型暫選**：2026-08-14 工作台留下三類證據。

- P0 驗了 leaf process 的 argv、raw stdin／stdout／stderr、exit／signal／啟動錯誤，以及某些結果不明情況不自動重跑。
- P1 驗了 Task-local Call、parent／child 關係與部分 crash-safe 發布；兩個假 child 的切片通過固定中斷點，但沒有真 scheduler 或 Agent。
- Janet 驗了純資料規則；它尚未在 Linux 取得正式寫入責任。

精確測試數量、命令與限制留在 [當日工作台](../workbench/2026-08-14/README.md)，避免正式設計隨測試增加而反覆改寫。

## 提升為正式行為前的門檻

一項原型暫選只有同時滿足下列條件，才可升為目前推薦或正式契約：

1. 有白話語意，不依賴某個 JSON 欄位才能解釋。
2. 有至少一個能推翻它的反例與恢復案例。
3. 已標出 Linux 與檔案系統假設。
4. C++ 能守住所有會造成外部作用或正式提交的硬邊界。
5. 格式若要可攜，跨實作 golden data 能一致重建。
6. 文件同步更新狀態，舊原型格式仍留在 workbench／archive，不反向成為真源。

在門檻前，實作可以換，證據可以推翻推薦；AOS 的核心方向仍由使用者已定的 Function 與 filesystem memory 模型約束。
