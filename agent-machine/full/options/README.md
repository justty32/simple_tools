# 尚未裁決的選項

這個目錄收集主線故意沒有鎖死的取捨。它的角色是讓人看見代價、安排小原型，不是偷偷把「目前推薦」升成使用者已定，也不是先發明 JSON、檔名或 CLI 契約。共同詞義與權威順序仍以[全套狀態](../00-STATUS-AND-SOURCES.md)為準。

## 選項如何進入主線

同一題可以用下列三種處理方式；它們是具體的決策路徑，不可混用成模糊的「以後再說」。

### 方案 A：直接定案

優點是實作者能立刻收斂介面，缺點是尚未測到的 crash、路徑或外部作用反例會變成昂貴的相容性負債。這只適合使用者已明確裁決的產品方向。

### 方案 B：為窄原型暫選

優點是能用一小段程式和測試取得證據；缺點是很容易把原型的 ID、檔案布局或 JSON 誤傳成正式 ABI。原型暫選必須寫清適用範圍與未測邊界。

### 方案 C：保留多案並指定下一個驗證

優點是誠實面對未知，並能比較真正影響使用感與安全性的差異；缺點是主線不能假裝已有完整細節。**目前推薦**採此方式，直到使用者裁決或小原型把一案的成本、錯誤面與操作感量清楚。

推翻此推薦的條件是：某個近期實作被這一題實質阻塞，而原型已能在固定範圍內排除較小方案；或使用者明確選定其中一案。即使如此，也只提升已驗過的邊界，不自動凍結 schema 或命令拼法。

## 共同護欄

- 使用者已定的是 Function 可由檔案或資料夾承載、執行中的 Function 實例叫 Task；Task 的完整起訖、資料夾入口和 Return ABI 都還沒定。
- 外部作用缺可信完整結果時，不可因重開或看到部分輸出就假裝成功，也不可自動重送。
- Agent root 的 path 身分、busy 三路與 machine-local 執行權威，不能由本目錄的任何便利方案推翻。
- 方案頁的程式片段只用來說明資料形狀；不代表正式命令、檔名、事件或存檔格式。
