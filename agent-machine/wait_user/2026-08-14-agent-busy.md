# bot-a 還在忙，第二件事怎麼辦？

> 已回覆 · 2026-08-14 · 本卡保留作決定紀錄

假設你剛交代 bot-a 一件事：

```bash
cd /home/mine/bot-a
./interact
> 整理今天的筆記
```

bot-a 還沒做完，你又交代：「順便檢查程式」。同一個 bot-a 不同時做兩件會改自己資料夾的工作。

## 已決定

普通的新呼叫預設這樣處理：

```text
bot-a 正在忙
-> 直接拒絕這次新呼叫
-> 清楚告知使用者
-> 不自動建立新 Task
```

需要時，使用者仍可明確選擇另外兩種操作：

1. **追加到目前 Task**：把新的 prompt 加進 bot-a 正在進行的 Task。
2. **建立排隊 Task**：明確建立另一個 Task 等待，而且必須一併寫清楚「目前 Task 到了什麼狀況，這件工作才可開始」。

因此 AOS 不會把普通呼叫偷偷變成排隊，也不會讓使用者以為被拒絕的工作其實已經保存。

若日後同一個 bot-a 同時執行兩個 Task，bot-a 的資料夾內必須看得到目前有哪些 active Tasks；這份資訊由 AOS 管理，但是否允許兩個 Task 同時寫檔仍未決定。

## 還沒決定

- 追加的 prompt 要在目前 Step 或 Round 的哪個安全邊界生效。
- 排隊條件有哪些正式選項，以及命令要怎麼寫。
- 目前 Task 的結果不明時，後面的排隊 Task 應等待、取消，還是交給使用者處理。

這些會先做原型比較，不需要現在再回覆。
