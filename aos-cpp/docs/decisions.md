# 設計決策記錄

這份文件是 `PLAN.md` 的替代品。`PLAN.md` 原本是建置前寫給實作者的規格書，
M0–M6 全部完成之後，裡面「要做什麼」「怎麼分工」「里程碑判準」那些規劃語言
已經沒有意義，`docs/architecture.md`、`docs/format.md`、`docs/exec.md`、
`docs/capi.md`、`docs/cxxapi.md` 也已經把「現在是怎麼運作的」講清楚了。但
`PLAN.md` 裡有幾段解釋「為什麼這樣決定」的內容，在上述文件裡沒有對應的位置；
直接刪掉 `PLAN.md` 就會永久失去這些設計決策的記錄。這份文件只保留「為什麼」，
不保留「怎麼做」與「要做什麼」——後兩者已經是程式碼與其他 `docs/*.md` 的責任。

## 為什麼從九行格式換成 JSON

換成 JSON 的理由只有一個：**要能加欄位**。九行格式（八欄位 + 一行空白分隔）
加一個欄位，等於改變每筆記錄佔用的行數——所有既有檔案的行位置全部錯位，所有
既有 reader 也全部錯位。這是破壞性升級，沒有例外。JSON 物件加一個鍵不會動到
既有檔案。

**不是**為了預留 `_type` 這種型別辨別鍵，也不是為了美觀或人類好讀（指令檔本來
就不該手寫）。目前只有一種記錄型別，預留一個沒人要用的辨別鍵，只會讓每個讀者
都要多問一句「還有哪些型別」。真的出現第二種記錄型別時再加——JSON 的好處正是
那時候加一個鍵也不會破壞任何既有檔案，跟一開始就多留一個沒人用的鍵是兩回事。

## 實作陷阱（docs 沒提到的部分）

`docs/architecture.md`、`docs/format.md`、`docs/exec.md`、`docs/capi.md` 已經
各自收留了大部分容易無聲壞掉的規則——整份讀進來的原子性、fork 後的
async-signal-safe、`extern "C"` 例外邊界、`env` 鍵檢查、`write_one`／
`write_all` 先驗證後寫入、記錄序號回報、`setpgid` 兩邊都要呼叫、指令檔 fd
的 close-on-exec，都已經有家。以下是還沒被涵蓋、但改動時很容易無聲破壞的
幾條：

1. **`nlohmann/json.hpp` 絕對不能出現在 `include/` 底下任何公開標頭。** 一旦
   進了公開標頭，這個 `.so` 就變成「只給用同一版 nlohmann、同一組編譯旗標的人
   用的函式庫」，`-fvisibility=hidden` 救不了這件事。只能出現在 `src/format.cpp`。
2. **測試連結不到內部符號。** `-fvisibility=hidden` 會讓沒標 `AOS_API` 的東西
   在 shared library 裡不可見。解法是用 `add_library(aos_objects OBJECT ...)`，
   測試連 object library，`aos` 連同一組 objects；不要為了測試而 export 內部
   符號。
3. **子行程用 `_exit()`，不是 `exit()`。** 後者會跑父行程登記的 `atexit`
   回呼，那些回呼假設自己還在父行程的狀態裡，在 fork 出來的子行程裡執行是
   未定義行為。
4. **`EINTR` 要重試。** `waitpid`、`read`、`open` 都要包
   `do { ... } while (rc == -1 && errno == EINTR)`；漏掉任何一個都會在訊號
   頻繁的環境下變成間歇性的假失敗。
5. **`dup2` 之後要關掉原本的 fd**（除非它剛好就是目標 fd），否則子行程會多
   帶一個不該繼承的檔案描述符活過 `execve`。
6. **macOS 沒有 `execvpe`、沒有 `pidfd_open`，不要用。** `CLOCK_MONOTONIC`、
   `setpgid`、`nanosleep` 都有，可以放心用。
7. **不要用 `system()`。** `argv` 必須是陣列，字串組合出來的指令行就是 shell
   injection；而且重導向／`cwd`／`env` 必須發生在 `fork` 與 `exec` 之間那個
   縫隙裡設定，`system()` 沒有那個縫隙可以插入。

### 已作廢：JSON 巢狀深度限制

深度限制原本規劃要「在解析中生效，而不是解析後才檢查」（後者發現的時候堆疊
已經爆了）。這條規則現在整個作廢——深度限制連同其他四條上限（單筆物件位元組
上限、整份輸入位元組上限、`argv` 元素數上限、`env` 條目數上限）一起被拿掉了，
見 `docs/format.md`。深層巢狀輸入仍然會讓解析器堆疊溢位，但那已經被接受成
「指令來源必須可信」的一部分，不再是需要在解析中防範的錯誤路徑。這裡留紀錄
純粹是避免有人讀到舊 commit 或舊分支時，誤以為深度限制仍然有效。

## 刻意不做的事

寫下來是為了避免有人「順手加一下」：

- **`_type` 鍵。** 理由見上一節：目前只有一種記錄型別，真的出現第二種再加。
- **控制流（if／迴圈／並行／相依）。** 這些不是欄位，是語言。要條件就
  `argv: ["sh","-c","..."]`，要並行就 `xargs -P`，要編排就巢狀呼叫
  `aos-cpp` 自己。把結構搬進格式，就會失去「同時活著的行程數 = 巢狀深度」
  這個資源保證，然後得自己管排程、fd 上限、PID 上限。
- **背景執行／不等待。** 同上，會破壞循序執行的資源上界。真的要，之後可以
  當成一個新欄位加——這正是換成 JSON 買到的東西。
- **`rlimit`／`umask`／`setuid`。** 都是合理的欄位，但目前不做。目前只用
  `timeout_ms` 一個欄位證明「加欄位是免費的」就夠了。
- **舊格式（九行）的讀取或轉換工具。** 舊 repo 還在，舊檔案給舊 binary 讀，
  `aos-cpp` 不提供相容層。
- **常駐／daemon 模式。** 跑一次、吃到 EOF、收工。要「一直跑」是觸發者
  （cron／systemd）的事，不是這個工具的事。
- **重新對齊／容錯續跑。** 任何解析失敗都停止整輪，不嘗試跳過壞記錄繼續
  執行後面的。
