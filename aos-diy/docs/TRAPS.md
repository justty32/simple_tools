# 陷阱總表

每一條都是在 `../aos-simple/` 真的踩過的，不是理論上的注意事項。

**`先講`** = 沒有症狀或症狀出現時已來不及，動手前就要說
**`先撞`** = 症狀明確且無害，讓他親自踩一次記得最牢

導師自己要全部記得；給使用者的時候按 Stage 給。

---

## 語言與建置

| | Stage | 症狀 | 真相 |
|---|---|---|---|
| `先撞` | 1 | 一團看不懂的編譯錯誤 | **`stdin`／`stdout`／`stderr` 是 `<cstdio>` 的巨集**，不能當成員名。一律加 `_path` |
| `先講` | 0 | Release 建置測試「全過」但其實沒跑 | **不要用 `assert`**，`NDEBUG` 下它整個消失 |
| `先講` | 1 | 之後有人踩到「空的 user」 | 可選欄位用 `std::optional`，**不要用空字串代表沒給**——空字串是合法的值 |
| `先講` | 全部 | 程式碼變難讀 | C++26 新東西**不要為用而用**。`std::expected` 在 validate 上真的好；`fork`/`exec` 那層老實寫 C |

## 併發與收工

| | Stage | 症狀 | 真相 |
|---|---|---|---|
| `先講` | 2 | 收工時待辦被安靜丟掉 | **「叫它收工」和「把待辦丟掉」是兩件事**。用哨兵，排在前面的照做完 |
| `先撞` | 2→6 | **程式停住不動** | `take()` 收工後**重複呼叫都要回「收工了」**。哨兵取出來要**放回去**，否則 N 條 worker 只有一條收得到 |
| `先講` | 6 | TSan 報 race | 一條 worker 一個 `Loop` 實例（stats 不是 atomic），共用 queue 與 executor |
| `先講` | 6 | peak 記到偏低的值 | 記最高點要用 compare-exchange 迴圈，不是 `if (now > peak) peak = now` |
| `先撞` | 7 | 「排在前面的先做完」不成立 | **排序容器裡不能放哨兵**，它會被優先值排到不知道哪去。改用旗標 ＋ `notify_all` |
| `先講` | 7 | 同優先權的順序不可重現、有人餓死 | **同分必須嚴格 FIFO**，用遞增序號當第二鍵 |
| `先講` | 9 | 收工時工作被丟掉 | **只看 queue 空不空是錯的**：worker 手上那個不算，而且處理途中會生出新工作。要數「進了系統還沒出去的」 |
| `先講` | 9 | 計數永遠歸不了零 / 提早歸零 | `push` **先 +1 再 push**；observer 包裝**先跑使用者的再 -1** |

## fork / exec（★ 密度最高的一區）

| | Stage | 症狀 | 真相 |
|---|---|---|---|
| `先講` | 4a | 一個輸出量大的子行程把整條 loop 卡死 | **三條串流走檔案不走管線**。走檔案這整類問題不存在 |
| `先講` | 4a | 詭異的當機 | fork 後、exec 前**只能用 async-signal-safe 的東西**。argv/envp 在 fork 前備好 |
| `先講` | 4a | 整個服務的 cwd 被改掉 | `chdir` 在**子行程**裡做 |
| `先講` ★★ | 4a | **證據檔裡出現不是子行程印的東西**。一般建置看不到，只有 sanitizer 會現形 | **fork 前 `fflush(nullptr)`**。子行程繼承 parent 沒沖出去的 stdio buffer，然後 `dup2` 把 fd 1 指到證據檔 |
| `先講` ★★ | 4b | 「執行檔不存在」跟「程式回 127」**完全一樣** | **self-pipe**：子行程 exec 前開一條 `CLOEXEC` 管線，失敗就寫 `errno` |
| `先講` ★★ | 4c | `exit 137` 跟 `kill -9` **完全一樣** | 用 `waitpid` 的**原始 status** ＋ `WIFEXITED`／`WIFSIGNALED`。`0x8900` vs `0x0009` |
| `先講` ★★ | 4c | 斷電後 exit 檔存在但**是空的**（看起來像有結論）；或 rename 整個沒發生 | **`fsync(檔案)` → `rename` → `fsync(目錄)`**。順序不能反；第三步最常被忘記 |
| `先講` | 4c | 「檔案存在」不再代表「這一次跑完了」 | 執行前先 `unlink` exit 檔 |
| `先講` ★★ | 4d | 同一個 `Call` 在不同人手上結果不同 | **預設環境是乾淨的**，不繼承本行程的。裡面只放 `PATH` |
| `先講` | 4d | 4b 做出來的區分消失了 | env 檔要「先 source 再捕捉環境、自己 execve」，**不是** `sh -c '. env; exec prog'` |
| `先講` | 4d | 拿一份**空環境**去跑程式，而且沒有錯誤 | env 傾印後要印**哨兵**。env 檔裡一句 `exit 0` 會讓 `sh` 在 `env -0` 前結束 |
| `先講` | 4d | 目標程式的 stdin 被吃掉一段 | env 檔的 stdin 給 `/dev/null`，stdout 導到 stderr |
| `先講` | 4e | 用到錯的 PATH | **不要用 `execvp`**，它查找時用呼叫端 `environ` 的 PATH。自己寫，約 30 行 |
| `先講` ★★ | 8 | 工作「被砍了」但機器上還有東西在背景跑 | **砍行程群組不是砍 pid**。`setpgid(0,0)` ＋ `kill(-pgid, …)` |
| `先講` | 8 | 子行程來不及收尾 | 先 SIGTERM、等寬限、再 SIGKILL。★ 就算它之後乾淨 `exit(0)` 也要記成逾時 |
| `先講` | 8 | 逾時跟「外面有人砍它」分不開 | `timed_out`／`output_capped` 是**獨立旗標**，不是新 Status |
| `先講` | 8 | 不用逾時的人也付輪詢成本 | 不限的時候走**阻塞 `waitpid`** |

## 語義（總規矩，每一步都適用）

| | 症狀 | 真相 |
|---|---|---|
| `先講` | 呼叫端不知道能不能重跑 | **`Rejected` 保證什麼都沒發生**；`LaunchError` 是試過了但沒起來 |
| `先講` | 重複執行已經發生過的作用 | **`Unknown` 不是失敗**，是「不知道」。所以它**不寫 exit 檔** |
| `先講` | 讀到的結論不知道是誰的 | **一個 `Call` 的 exit 檔只能有一個人寫**。fan-out 時三個證據路徑都要換 |
| `先講` | `Call` 越長越大 | **機制在核心，政策在各條 loop**。優先權、逾時、上限都不進 `Call` |
| `先講` ★★ | 極難重現的死鎖 | **不要在 Executor 裡同步等另一條 loop**。改成 A 推 B、B 推 C |
| `先講` | 記憶體一路吃到爆 | loop 之間的圖要**有向無環**。需要環就在 `Call` 裡帶計數並設上限 |

## 輸入層

| | Stage | 症狀 | 真相 |
|---|---|---|---|
| `先講` | 10 | 打錯字的 key 被安靜吞掉 | **不認得的 key 要拒絕，不是忽略** |
| `先講` | 10 | emoji／中文壞掉 | `\uXXXX` 要處理 **surrogate pair** |
| `先講` | 10 | 一個壞請求害整條輸入中斷 | **一行一個物件**。串流式 parser 碰到壞語法就不知道下一個從哪開始 |
| `先講` | 10 | 一個裸換行弄壞整個格式 | 字串裡沒跳脫的控制字元要擋 |
| `先講` ★★ | 10 | 同機的其他使用者拿到你的 shell | socket **0600**，而且是 **bind 前收緊 umask**，不是 bind 後 chmod |
| `先講` | 10 | 收工時跟 `accept` 競態 | 停止服務用 **self-pipe**，不要在信號處理常式裡 `close(listen_fd)` |
| `先講` | 10 | client 按 Ctrl-C 讓整台服務消失 | **擋 SIGPIPE**（子行程那邊要還原成 `SIG_DFL`） |

## 測試本身

| | 症狀 | 真相 |
|---|---|---|
| `先講` | 測試「全過」但沒驗到東西 | Stage 0 一定要**真的看到紅色**再往下 |
| `先撞` | 測試永遠不結束 | shell 裡光禿禿的 `wait` 會連背景的服務一起等 |
| `先講` | 一整類 bug 從來沒被抓到 | **動過 fork 那段就跑 `make sanitize`**。有些東西只有那一輪會現形 |
| `先講` | 比較永遠是 false | 注意型別：容器比較要用對的方式，`slurp` 之類的回傳型別要確認 |
