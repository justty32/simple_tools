# 指令檔格式

一個指令檔裡放很多筆指令，每一筆佔九行：八行欄位，再加一行固定為空的分隔。沒有
標頭、沒有結束標記 —— 那一行空白分隔就是一筆的結束，也是下一筆的開始。

這份文件說明格式本身：哪一行放什麼、哪些字元有特殊意義、哪些沒有。至於這些欄位
在執行時會發生什麼事，看 [exec.md](exec.md)。

## 九行分別是什麼

| 行 | 欄位 | 內容 |
| --- | --- | --- |
| 1 | argv | 要執行的指令和它的引數，用 Tab 分隔 |
| 2 | stdin | 標準輸入要從哪個檔案讀 |
| 3 | stdout | 標準輸出要寫到哪個檔案 |
| 4 | stderr | 標準錯誤要寫到哪個檔案 |
| 5 | exit | 結束狀態要記到哪個檔案 |
| 6 | cwd | 執行時的工作目錄 |
| 7 | env | 環境變數本身，用 Tab 分隔的 `KEY=VALUE` |
| 8 | extra | 保留，目前不使用 |
| 9 | （分隔） | 固定為空的一行，隔開這一筆和下一筆 |

第 2 到 8 行留空是合法的，而且是常態 —— 留空代表「照預設來」，各欄位的預設行為
寫在 [exec.md](exec.md)。第 9 行則**必須**為空：它是分隔，不是欄位，非空就代表
記錄錯位了（見 [錯位現在測得到了](#錯位現在測得到了)）。

## 一個完整的例子

以下用 `→` 代表一個 Tab 字元，`⏎` 代表行尾的換行：

```text
echo→hello world⏎          ← 第 1 行：執行 echo，帶一個引數 "hello world"
⏎                          ← 第 2 行：stdin 留空
out.txt⏎                   ← 第 3 行：輸出寫進 out.txt
⏎                          ← 第 4 行：stderr 留空
status.txt⏎                ← 第 5 行：結束狀態寫進 status.txt
⏎                          ← 第 6 行：cwd 留空
⏎                          ← 第 7 行：env 留空，代表繼承呼叫者的環境
⏎                          ← 第 8 行：extra 留空
⏎                          ← 第 9 行：空白分隔，隔開下一筆
```

注意 `hello world` 中間的**空白是普通字元**，它跟 `echo` 是兩個引數，不是三個。
只有 Tab 會切開引數。

用 shell 產生這一筆：

```sh
printf 'echo\thello world\n\nout.txt\n\nstatus.txt\n\n\n\n\n' > insts
```

最後那個多出來的 `\n` 就是第 9 行的空白分隔。

## argv 行：只有 Tab 有意義

第一行用 Tab 把指令和引數切開，除此之外**沒有任何特殊字元**：

- 空白、`'`、`"`、`\`、`$`、`*` 全都是普通字元，原樣傳給程式
- 沒有引號可用，也不需要 —— 因為沒有東西需要被引起來
- 沒有跳脫字元，`\t` 就是反斜線加上字母 t 兩個字元
- 不會做萬用字元展開、不會做變數替換

這是刻意的取捨。一旦有了引號和跳脫，就得回答「引號裡的引號怎麼寫」這類問題，而
每個工具的答案都不一樣。改成只認 Tab，規則就一句話講得完，代價是**引數本身不能
含有 Tab**。

### 相鄰的 Tab 會產生空引數

```text
a→→b     ← 三個引數："a"、""、"b"
a→       ← 兩個引數："a"、""
→a       ← 兩個引數：""、"a"
```

這通常不是你要的，但它是規則的自然結果，而且有時候真的需要傳一個空引數。

### 一個例外：整行只有一個空引數是不行的

如果 argv 行整行是空的，那它會被當成「這筆指令沒有任何引數」而被拒絕
（`EMPTY_ARGV`），而不是「一個空引數」。因為兩者序列化出來長得一模一樣，寫入端
也會擋下這種指令，避免寫出一筆讀不回來的記錄。

## env 行：一樣只有 Tab 有意義

第七行放的是環境變數**本身**，不是一個檔案路徑。切法跟 argv 行完全一樣：Tab 分隔，
沒有引號、沒有跳脫、沒有變數展開。

```text
PATH=/usr/bin:/bin→LANG=zh_TW.UTF-8→EMPTY=
```

規則：

- 每個 token 必須是 `KEY=VALUE`，也就是**要有 `=`，而且 `=` 不能在最前面**
- 值可以是空的（`EMPTY=`），值裡面也可以有 `=`（只有第一個算分隔）
- 不合格的 token 是 `ENV_ENTRY_MALFORMED`，整筆記錄作廢
- 沒有註解、沒有空行 —— 那是「一行一筆」的檔案才有的東西，這裡一行就是全部

**跟 argv 行唯一的差別是空行的意義**：argv 行空的是錯誤（`EMPTY_ARGV`），env 行
空的是合法的，代表「沒有任何變數」，也就是繼承呼叫者的環境。執行時的完整語意看
[exec.md](exec.md#env環境變數)。

## 每一行都必須以換行結尾

**包括第九行那行空白分隔。** 這是唯一一個容易踩到的細節。

原因是：如果最後一行沒有換行，就沒辦法分辨這兩種情況 ——

- 檔案完整結束，而最後那行分隔剛好是空的
- 檔案被截斷了，記錄根本還沒寫完

要求每一行（含最後的分隔行）都以換行收尾，這兩者就分得開：讀到第九行的換行才算
一筆完整的記錄，否則就是 `INCOMPLETE`。

LF（`\n`）和 CRLF（`\r\n`）都接受，讀取時 CRLF 的 `\r` 會被去掉。但只有在行尾
的 `\r` 才會被去掉，行中間的 `\r` 是普通資料。寫入時一律輸出 LF。

## 一筆接一筆

記錄之間用一行空白分隔。八行欄位之後那一行空白就是分隔，它下面一行才是下一筆的
argv：

```text
echo→first⏎          ┐
⏎                    │
⏎                    │
⏎                    │ 第一筆（八行欄位）
⏎                    │
⏎                    │
⏎                    │
⏎                    ┘
⏎                    ← 第 9 行：空白分隔
echo→second⏎         ┐
⏎                    │
⏎                    │
⏎                    │ 第二筆（八行欄位）
⏎                    │
⏎                    │
⏎                    │
⏎                    ┘
⏎                    ← 空白分隔（也是檔案結尾前的最後一行）
```

分隔行**必須**是空的。它靠**位置**辨識 —— 讀完八行欄位之後那一行就是它 —— 所以
它是空的不會跟「某個欄位剛好留空」混淆。這一行空白就是讓錯位測得到的關鍵，代價
只是每筆多一個 `\n`（見 [錯位現在測得到了](#錯位現在測得到了)）。

## 不能出現的字元

| 位置 | 不能有 | 為什麼 |
| --- | --- | --- |
| argv 的任一引數 | Tab | 那是引數分隔符 |
| argv 的任一引數 | `\n`、`\r` | 那會變成換行，把一筆記錄拆成兩筆 |
| env 的任一筆 | Tab | 那是項目分隔符 |
| 第 2 到 8 行 | `\n`、`\r` | 同上 |

第 2 到 6 行和第 8 行**可以**有 Tab，它在那裡只是普通字元。所以路徑裡有 Tab 沒
關係，引數和環境變數裡有才有問題。

寫入端（`aos_instruction_write`）會在寫出任何一個位元組之前檢查這些規則，所以一筆
不合法的指令不會弄髒你的輸出檔。

## 大小限制

| 限制 | 預設值 | 說明 |
| --- | --- | --- |
| 單筆記錄的引數數量 | 256 | 超過就是 `TOO_MANY_ARGS` |
| 單筆記錄的環境變數數量 | 256 | 超過就是 `TOO_MANY_ENV` |
| 單筆記錄的位元組預算 | 1 MiB | 超過就是 `TOO_LONG` |

位元組預算算的是八行欄位內容的長度總和，**不含行尾換行**（CRLF 的 `\r` 會算進去，
因為它是在檢查之後才被去掉的）。第 9 行那行空白分隔本該是空的，不計入預算。

這個預算存在的理由是安全而不是效能：讀取端會為了容納一行而不斷擴充緩衝區，沒有
上限的話，一個畸形的檔案就能把記憶體吃光。所以預算永遠存在，傳 0 會被當成參數錯誤
而不是「不設限」。

三個限制都可以在執行期問出來，不要寫死：

```c
size_t max_args  = aos_inst_argv_max();
size_t max_env   = aos_inst_env_max();
size_t max_bytes = aos_inst_record_max_bytes();
```

## 讀取時可能拿到的狀態

| 狀態 | 意思 |
| --- | --- |
| `AOS_INST_OK` | 讀到完整的一筆 |
| `AOS_INST_EOF` | 檔案乾淨地結束了，沒有下一筆 |
| `AOS_INST_INCOMPLETE` | 讀到一半檔案就沒了 —— 不足九行，或最後一行沒有換行 |
| `AOS_INST_EMPTY_ARGV` | argv 行是空的 |
| `AOS_INST_TOO_MANY_ARGS` | 引數超過上限 |
| `AOS_INST_ENV_ENTRY_MALFORMED` | env 的某一筆不是 `KEY=VALUE` |
| `AOS_INST_TOO_MANY_ENV` | 環境變數超過上限 |
| `AOS_INST_MISSING_SEPARATOR` | 八行欄位之後那一行不是空的 —— 記錄錯位了 |
| `AOS_INST_TOO_LONG` | 這筆記錄超過位元組預算 |
| `AOS_INST_READ_ERROR` | 檔案本身讀不動 |

**任何一種失敗（包含 `EOF`）都會讓指令物件回到空的狀態。** 不會有「讀了一半的
記錄」這種東西留在裡面，前一筆的內容也不會殘留。

`INCOMPLETE` 和 `TOO_LONG` 是終點，不是「等一下再試」—— 已經讀掉的位元組沒辦法
退回串流，所以遇到這兩個就該停下來。

## 為什麼是這個格式

- **八行固定欄位，不是 key=value**：解析器不需要認得欄位名稱，要加欄位就在分隔行
  之前多一行，舊檔案不會突然多出意義不明的東西。
- **Tab 分隔，不是空白分隔**：檔案路徑裡常常有空白，Tab 幾乎不會。
- **沒有引號和跳脫**：規則單純到可以完整寫在這一頁裡。
- **純文字，一行一欄位**：`grep`、`sed`、`head` 都能直接用，不需要專用工具。
- **記錄之間一行空白分隔**：多一個 `\n` 的代價，換來錯位測得到（見下一節）。

代價是引數不能含 Tab、不能含換行。

## 錯位現在測得到了

早期版本的記錄之間沒有分隔符號，少一行或多一行會讓下一筆的行被吸收進來補滿八行，
產生一筆**語法合法、但欄位來自別筆**的記錄 —— 解析器不會報錯，拿去執行就是**跑一個
你從來沒寫過的指令**。

第 9 行那行空白分隔就是為了關掉這個坑。少一行或多一行，會讓原本該落在分隔位置的
空白行被非空的資料頂掉，於是：

- 那行不是空的 → `MISSING_SEPARATOR`，直接指出錯位；
- 或者位移把某個欄位推進 env 那一行、變成不合法的 `KEY=VALUE` → `ENV_ENTRY_MALFORMED`；
- 或者剛好把記錄推到檔尾之外 → `INCOMPLETE`。

三種都是**明確的失敗**，串流會停在出事的地方，不會默默解出一筆別筆拼出來的指令。
落到哪一種，看那一行刪／加在哪裡；重點是不再是無聲的。完整的執行面說明在
[exec.md](exec.md#錯位現在會被空白分隔行擋下)。

即使如此，**還是用 `aos_instruction_write` 產生指令檔，不要手寫、不要用 shell 拼接。**
寫入端整筆驗證完才開始寫，連錯位的機會都不給；偵測是最後一道防線，不是第一道。
