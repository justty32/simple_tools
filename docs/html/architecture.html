設計說明

模組結構、#embed 嵌入、跨平台策略、靜態連結。

總覽 使用指南 設計說明

模組結構（每檔 ≤150 行）

檔職責
src/main.cpp進入點；解析 argv[1] 並派發
src/commands.{hpp,cpp}cmd_new()、cmd_build()、print_usage()
src/templates.{hpp,cpp}#embed 嵌入範本並替換 @NAME@
src/platform.{hpp,cpp}make_program()、exe_suffix()、dcap_home()、run()
src/util.{hpp,cpp}write_file()、ensure_dir()、path_exists()

所有 OS 專屬分支收在 platform.*，其餘保持平台中立。

模板嵌入：#embed

範本存成 templates/ 下的真實檔案（可正常編輯 / diff），編譯期用 C++20 的 #embed（GCC 15+）嵌入：

constexpr char kCppMakefile[] = {
#embed "../templates/cpp/Makefile"
    , 0};   // 尾端補 0 → C 字串

執行期把 @NAME@ 替換成專案名。範本與程式碼分離，且不需額外 codegen 工具，只靠 g++。

跨平台策略

面向作法
make 程式Windows 先試 mingw32-make 否則 make（反之亦然）
產物副檔名exe_suffix() + find_binary() 以 std::filesystem 找實際檔
共用 lib 路徑DCAP_HOME + Makefile 內 ifeq ($(OS),Windows_NT) 後援
執行子程序std::system；呼叫前 flush 自身 stdout 避免輸出交錯

靜態連結

dcap 本體與產生的專案都用 -static：dcap.exe 不依賴 libstdc++-6.dll / libgcc_s_seh-1.dll，產生的小工具也是單一可執行檔。

為何用 find

$(shell find . -name '*.cpp') 做無限遞迴，新增檔案不用改 Makefile。Windows 上依賴 Git 附帶的 find/sh。
