CONTRACT · CONTROL FLOW · DURABILITY · EFFECT

不要選一套「萬能 Agent framework」

七套框架像七種不同的 runtime 元件：有的校驗 wire data，有的切換 actor，有的排 workflow，有的保存 checkpoint。工程問題不是誰功能最多，而是每個責任有沒有清楚 owner、identity、authority 與 crash 語意。

真正值得先做的是 effect gate

Response不可信輸出
Schemanormalize / validate
Intent尚未執行
Policygrant / approval
Executorsandboxed effect
Receiptevent / checkpoint

這條路同時吸收 Instructor、LightAgent 與 LangGraph 的優點，也保留 freepy 的 Round/Step、typed operation 與 OS enforcement。

七套框架，拆成六種零件

Schema compiler

Instructor：provider response 先 normalize、validate；re-ask 是新的真模型 Step，不是免費 parser retry。

Handoff intent

Swarm：把換 agent 表成普通 tool result；target name/path 只是請求，不能創造 grant 或 budget。

Small workflow AST

PocketFlow：prep → exec → post 與 action edge 清楚；shared mutable dict 不適合 durability。

Lazy operation graph

MiniChain：描述與求值分離、保留 snapshot；global context 與 shell backend 不採用。

Policy / task layer

LightAgent / CrewAI：借 hook、approval receipt、trace、Task output contract；不搬大 agent object 與 prompt routing。

Durable graph runtime

LangGraph：借 reducer、pending writes、interrupt/checkpoint；不等於外部 effect exactly-once。

五組最重要的「不是」

時間與 identity 要正交

一個 workflow node 可能完全不叫模型，也可能包含多個 model Steps；validation re-ask 會增加 Step，retry attempt 卻不該偷換 task identity。因此 event 可同時帶：

round_id · step_no · workflow_run_id · workflow_node_no · task_id · tool_call_id · attempt_no
框架內部名稱進 freepy 邊界時必須 normalize；不要把 turn、node、attempt 全壓進同一個 counter。

採用順序：從可觀測到 durable

  1. 共同 records：ModelAttempt、Intent、PolicyDecision、Approval、Receipt、Checkpoint、Interrupt。
  2. 結構化模型邊界：bounded re-ask，raw response 與 usage 都留下。
  3. 工具閘門：schema → grant → policy → approval → sandbox executor。
  4. 最小 workflow：sequential、branch、subflow、bounded retry、interrupt/resume；先不做 generic Pregel。
  5. task/handoff：handoff、delegate、spawn 使用三種 typed operation。

第一個可驗收切片應讓每次 effect 都能回答「誰要求、看見什麼、誰批准、實際做了什麼、結果是否已知」，而不是先支援七套 API。
