Security boundary · 02

每一層只解決自己的問題

Container 不是單一保護罩，而是把多個 Linux 機制組起來：namespace 改變「看得見什麼」，cgroup 限制「能用多少」，capability 與 seccomp 縮小「能做哪些核心操作」，網路拓樸決定「封包能走去哪裡」。

隔離不是一顆總開關

VISIBILITY

Namespace／mount

像替每台測試機接上不同配線盤。程式只能解析到被掛入的 filesystem、process 與 network view。

QUANTITY

cgroup v2

像電源供應器的 current limit 與通道配額，控制 CPU、memory、PID 與部分 I/O；不管理路徑或 secret。

PRIVILEGE

Capability／no-new-privileges

把傳統 root 權能拆細並禁止執行後提權。--cap-drop=ALL 是降低攻擊面，不是完整 sandbox。

SYSCALL

seccomp／Landlock

前者過濾 system call，後者可限制 filesystem 存取。兩者是額外防線，不理解 agent 的語意權限。

ROUTING

Network topology

真正的網路邊界來自沒有直接 route、只有獲准 gateway；不是相信程式會遵守 proxy 環境變數。

CREDENTIAL

Secret broker

長效 key 留在可信任服務，agent 只拿短效 session token。這限制 credential 暴露，不會審查 prompt 內容。

三種資源機制不要混用

rlimit · 單一 process 的局部保護

可限制 CPU 秒數、address space、open files、process 數。它不建立新的 filesystem 或 network view，而且若套在同 process Python tools，supervisor 也會一起受限。

cgroup · 一群 process 的資源帳戶

提供 CPU、RAM、PID 和 I/O 的分組 accounting/enforcement。它像電力配電盤，但不會阻止程式讀取某條路徑或連到某個 hostname。

container · 多種 OS 邊界的組合

Podman 組合 namespace、cgroup、mount、identity、capability 與 lifecycle。仍需正確 policy、無旁路拓樸和啟動驗證；「用了 container」本身不是安全證明。

application limit · 語意與成本控制

agentloop 能計算 Step、tool call、token 與時間。它看得懂 agent protocol，卻不能取代 kernel 對 process 的存取控制。

三種網路模式

ISOLATED

沒有直接外網

Agent 只加入 internal network。它可能仍能連同網路上的 model broker，所以這不代表資料絕對不會離開環境。

PROXY

唯一出口是 allowlist proxy

Agent 沒有 default route；雙網卡 proxy 才能出網，並按 hostname／port 拒絕其他目的地。一般 HTTP workload 優先用這個模式。

ROUTED

精確允許非 HTTP 流量

以 static route 與 nftables 限定 CIDR、protocol、port，適合 TCP／UDP／ICMP 等需求，但複雜度與攻擊面較高。

NONE

完全不建立網路需求

最小版本直接使用 --network=none。若工作不需 LLM 或下載，這是最容易驗證的預設。

Allowlist 只限制目的地，不限制送出的內容。 允許 GitHub，就可能向 GitHub 外傳資料；共用 CDN、DNS 與可信 broker 也都是剩餘風險。

ASF 最值得借用的不是某個 flag

ASF 的核心價值是完整 lifecycle：CLI 先把 manifest 編譯成不可變 session plan，建立 rootless Podman 資源，再用 throwaway container 做正向與反向探針。任一安全 deny check 失敗便 fail closed，不啟動 workload。

  1. Filesystem：只 bind-mount 宣告的 repository，逐一標示 ro/rw；其他持久狀態使用 named volume。
  2. Process：container 內非 root、drop capabilities、no-new-privileges，不掛 Podman socket。
  3. Network：從 container 內驗證無 default route、無直接 DNS、private address 與禁止 port 不可達。
  4. Secret：長效 provider key 只進 broker，agent 取得 session token；provider domain 從一般 proxy allowlist 移除。
  5. Evidence：保存 runtime plan、verification report、exit reason 與 cleanup report。

工程師容易誤解的詞

rootless

Podman daemon/container 不以宿主 root 執行，降低事故影響；不代表 container 內的程式天然無害。

bind mount

把宿主的既有路徑映射進 container。rw 仍會改到宿主原檔，必須精確縮小來源路徑。

tmpfs

記憶體中的暫存 filesystem；適合 /tmp、/run，結束即消失，但仍需大小與 mount option 限制。

fail closed

無法證明限制生效時拒絕啟動。不是把「proxy 壞了」與「deny policy 失效」都悄悄視為可繼續。

defense in depth

多層限制讓單一失誤不直接變成全面失守；它不是「執行任意惡意程式都絕對安全」的保證。

effective policy

OS 實際執行的狀態，不是 manifest 原本想表達的 declared policy；啟動探針量的是前者。
