Security boundary · 03

誠實標示目前的邊界

freepy 已有預算與部分路徑檢查，但 OS sandbox 仍在規劃。要分清「防誤用」和「隔離 hostile code」。

今天真正成立的保證

EFFECTIVE

已有效

  • 迴圈計算 Round、tool call、時間、token 與 model 預算。
  • 工具呼叫統一結算，超額時拒絕執行。
  • 狹窄檔案工具檢查 resolved path，可阻擋一般路徑越界。
  • shell=False 的 argv 避免 shell 二次解析。

NOT PROVIDED

尚未提供

  • run_shell 的 filesystem、network 或 child-process 隔離。
  • 同一 Python process 中每個 agent／tool 的不同 OS 權限。
  • 任意 executable 或未審查 Python tool 的 hostile-code isolation。
  • 每 agent 的 mount、user、network namespace 與 cgroup lifecycle。

run_shell 為何是高權限工具

subprocess.run(command, shell=True,
               cwd=str(get_root()), ...)

cwd 只決定起始目錄，沒有建立 mount namespace。子程序仍能碰宿主路徑、網路與其他 process；approval 和 timeout 只是額外防線。

命令黑名單不是邊界。 同一副作用可由變數、腳本、替代命令或語言 runtime 表達。

Thread 不是隔離單位

agentloop.run() 在呼叫它的 process 內執行 Python dispatch；搬進 worker thread 仍無 process 隔離。Thread 共用 address space、environment、descriptors 與宿主權限：

不能做每 agent 路徑視野

Agent A 與 B 若同 process，就不能靠 thread 讓兩者分別只見 A/B 目錄。

rlimit 會波及 supervisor

per-process 限制套在同 process 工具上，也會限制負責管理與回收它的可信任控制面。

Global state 會互相影響

工具可使用 os、socket 或第三方函式庫，亦可能破壞其他 agent 共用的程序狀態。

建議的正式邊界

freepy supervisor（可信任）
├─ immutable SandboxPolicy
├─ create / start / stop / inspect
├─ secret broker（長效 key 不下放）
└─ effective policy / exit / cleanup evidence
                     │
                     ▼
每個 agent 一個 rootless Podman container
├─ /workspace/task               rw
├─ /workspace/reference/*        ro
├─ read-only root + bounded tmpfs
├─ non-root + drop capabilities
└─ network none / internal only

要隔離完整 agent，就必須把 agentloop + tools 一起移進 container；只包住 shell，而 Python tools 和 LLM client 留在宿主 process，不能宣稱每實例隔離。

最小版本：刻意做窄

FILES

只掛需要的路徑

一個 task workspace 為 rw，零到多個 reference mount 為 ro；root filesystem 唯讀。

NETWORK

先從 none 開始

第一版用 --network=none。需要 LLM 時再加入 internal broker，而不是先給外網再嘗試封鎖。

IDENTITY

rootless、非 root

drop all capabilities、no-new-privileges、private IPC，不掛 Podman/Docker socket 或宿主 SSH agent。

RESOURCE

硬上限與 timeout

限制 CPU、RAM、PID、core dump 與 tmpfs；宿主 supervisor 能停止整個 container 並收割所有 children。

EVIDENCE

驗證 effective state

啟動 agent 前實測 mount、identity、resource 和 deny network；結束後記錄 cleanup 是否完整。

PLATFORM

先做 Linux／Podman

不要同時承諾 Windows backend。WSL 可承載 Linux Podman，但 WSL 本身不是每 agent 的隔離邊界。

落地順序

  1. Policy 與 renderer：定義 immutable SandboxPolicy，以 argv list 產生 Podman 命令並做純單元測試。
  2. 離線 container probes：驗 mount、identity、resource 與 network=none 的實際行為。
  3. Supervisor lifecycle：timeout、停止整個 container、清理 owned resources，保存 evidence。
  4. 完整 worker 移入：以狹窄 IPC 溝通；完成後才可宣稱每個 agent 實例彼此隔離。
  5. 有限網路：有需求時再加入 internal LiteLLM broker、短效 session token、allowlist proxy。
安全完成條件不是「Podman 成功啟動」。 必須證明拒絕路徑確實失敗、允許路徑可用、沒有直接出口，並且停止後資源已清除。
