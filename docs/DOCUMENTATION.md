# 文件與註解整理規則

## 資訊放置

| 類型 | 放置位置 | 應回答的問題 |
|---|---|---|
| README | package／目錄旁 | 現在能做什麼、怎麼使用、入口在哪 |
| PLAN | 尚未實作的 package 旁 | 要做什麼、依賴、非目標、驗收條件 |
| NOTES | 專案目錄 | 為何這樣決定、實測證據、容易重犯的坑 |
| 研究報告 | `docs/<topic>/` | 跨元件比較、來源、推論與建議 |
| 歷史材料 | `docs/archive/` | 已被取代但仍值得追溯的內容 |
| docstring／註解 | 程式旁 | 契約、限制、反直覺理由；不重述程式表面行為 |

`IDEAS.md` 只作尚未分類的收件匣；形成規格後移到對應 `PLAN.md`，落地後由 README
描述用法、NOTES 保存決策原因。

## 衝突處理

同一主題有衝突時，以最後編輯的內容為準。判斷順序如下：

1. 先看 Git 最後修改時間與文件內日期。
2. 同一次修改仍有衝突時，明確寫有「已定案／目前」且與程式行為一致者優先。
3. 舊文若仍有追溯價值，標明已被取代及替代文件；否則刪除重複內容。
4. README 不複製 PLAN／NOTES 全文，只連到唯一的詳細說明。

目前時間語彙的唯一來源是 [`freepy/agentloop/TURNS.md`](../freepy/agentloop/TURNS.md)：
一次完整 `agentloop.run()` 是 **Turn**，每次 `ask() → message` 是 **Round**；tool call
發生在兩個 Round 之間，不另造一個時間層級。

## 程式註解

- 公開介面用 docstring／header comment 說明輸入、輸出、錯誤與所有權。
- 行內註解優先解釋「為什麼不能用看似更簡單的寫法」。
- 不在註解保存 roadmap、工作日誌或會快速過期的模型／環境清單。
- 行為改變時，同一次修改更新相鄰註解與對應 README。
