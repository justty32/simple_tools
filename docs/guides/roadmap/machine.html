Roadmap 地圖agentloop後續

ROADMAP GUIDE · AGENT MACHINE

Agent Machine：現在開始的外圍機器層

它管理慢、昂貴、可能失敗的模型與工具工作：檔案狀態、排隊、記帳、恢復、驗證。先用 Python 做 reference，穩定後以 C++23／Janet 固化；它不是 Controller 的另一個名字。

先切開本地與外圍

本地：agentloop（loop + Handle + Limits）；Controller（較舒服的本地封裝）。外圍：Agent Machine；VFS transaction、executor、scheduler、resource。

Controller 不負責跨重啟或多 process；Agent Machine 透過 adapter 使用現有能力，不把 journal／lease 術語塞回它的日常 API。

ROADMAP 的後續概念

Command / Event

command 是請求做事；event 是驗證後記下的事實。請求可拒絕，事實不可任意改寫。

Store / transaction

store 保存資料。transaction 是一組更新要嘛全成功、要嘛都沒發生，避免「已結算但忘了排下一件事」。SQLite 是可考慮的單檔資料庫。

queue / scheduler / lease

queue 放待辦；scheduler 決定誰先跑；lease 是 worker 暫時取得執行權。它們處理多 worker，不是單一 Handle 的工作。

Candidate / evidence / verifier

模型可提 Candidate；evidence 是測試輸出、hash 或人工核准；verifier 才決定 Goal 是否真的達標。

為何不能 crash 就 retry？

讀檔與多數模型請求通常可重試；寄信、付款、部署、刪資料等工具可能已成功但回覆遺失，叫 unknown effect。恢復時要查證或人工處理，而不是盲目重跑。Agent Machine 因而必須先記 intent 與 operation id。

資源與安全仍是另一條線

endpoint 有成本、延遲、額度與不確定性；工具有權限與外部副作用。資源帳本可處理預算與 slot，但它不是 sandbox。真正的檔案、網路、CPU 與 process 隔離，仍要由 runtime、OS、container 或 VM 負責。

與 Pi bridge 的界線

Pi bridge 是 Pi extension 與 Python child process 的 JSONL control adapter。Pi 可操作一個獨立的 agentloop Round；它不借 Pi 的模型 endpoint，也不干預 Pi 本身的 agent loop。現階段它直接操作 Handle；等 Agent Machine operation protocol 穩定後，再新增 durable adapter。

這是 ROADMAP 導讀；正式規劃見 Agent Machine plan、ROADMAP 與 分層記錄。
