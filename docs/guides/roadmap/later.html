Roadmap 地圖Round 與 ControllerAgent Machine

M3–M7 · OUTWARD EDGES

後面不是「再加功能」，而是逐層補上能相信的邊界

前兩階段先回答「下一件工作是什麼、誰能執行」。後面才回答：它存得住嗎？模型說完成可信嗎？實際工具隔離了嗎？多個 agent 怎麼協作？能否用檔案般的介面觀察？

Milestone 3：讓完成可驗證，而不是聽模型說

Goal

使用者要達成的目標，例如「測試全過且檔案存在」。Round 是一次嘗試；Goal 可以經歷多個 Round。

Evidence

可追溯的證據，例如測試輸出、檔案 hash、人工核准。不是模型寫的一句「我完成了」。

Verifier

檢查 evidence 是否滿足 Goal 的機械或人工關卡。只有它能讓狀態進 achieved。

Restart

失敗時受 policy 限制的下一招：retry、repair、換模型、縮 context、升級給人、abort。模型只能建議。

未知工具副作用不能直接 retry：例如「寄信 API 可能已送出」時，先查證或人工處理，否則會重複寄信。

Milestone 4：identity、訊息與真的 runtime

Identity path 是穩定邏輯名字，如 /team/a；不是 OS PID、主機路徑，也不是 Linux cgroup。communication 先做可保存 mailbox，避免通知失敗時工作憑空消失。

Runtime 是實際跑 tool 的 worker。先有 fake backend 驗語意，後面才有 Linux executor：pidfd 管生命週期、cgroup 限資源、namespace 限可見性、seccomp/Landlock 限系統呼叫／檔案能力。沒有成功套用這些限制時，系統不能宣稱「已 sandbox」。

Milestone 5：memory 與 context pager

memory 是可保存、可追來源的資料；context 是這一步真的塞進模型的有限工作集。pager 依 token／bytes budget 挑選要載入、保留、冷凍或卸載的內容。正在執行的指令與尚未配對的 tool result 必須 pinned，不能被壓縮掉。

Milestone 6：team 不是多開幾個 bot

team 要有成員、權限 grant、資源配額、task/report 與可靠通知。父子團隊的 token、時間、endpoint slot 需要守恆；取消時還要處理 orphan、zombie 與互等造成的 deadlock。最後才做建立下屬的 saga，因為那是跨多個可失敗步驟的長交易。

Milestone 7：Plan 9 projection

把 goals、rounds、resources、events 等投影成像檔案系統可列、可讀、可查版本的 view。agentfs 不是新的真源；ctl 寫入也只能翻譯成既有 command，再走同一套檢查。先驗證 provider contract，最後才選 FUSE 或 9P transport。

Pi bridge、MCP、endpoint 各是什麼？

LLM endpoint 是 agentloop 的 bot.ask() 真正送模型請求的地方。Pi bridge 目前是 Pi coding agent 的 extension 透過 JSONL 啟動 Python 子 process，讓 Pi／人能看、pause、resume、end 一個獨立的 agentloop Round；它不借用 Pi 的模型 endpoint，也不插手 Pi 自己的 history、tool 或 agent 流程。

MCP 是未來可選的通用外部控制協定：可把 agentloop 功能包成一個 tool server 給不同 client 用。Pi bridge 目前直接操作 Handle；若日後真的建立 durable service，再另定能跨重啟的 adapter protocol。

本頁是白話導讀；正式順序以 ROADMAP.md 為準，Agent World 提供更廣的設計背景。
