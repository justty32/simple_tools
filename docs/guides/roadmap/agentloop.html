ROADMAP GUIDE · AGENTLOOP

agentloop：一個 agent 的本地核心

它只管一個 Round 怎樣前進：問模型、跑工具、在安全停點讓人介入。它不是資料庫、scheduler 或多 agent 平台。

Round 裡發生什麼

Round一次任務
Step問模型一次
tool batch完整跑工具
下一個 Step帶結果再問

例如「修好測試」：讀檔、跑測試、改檔、重跑，整趟是一個 Round。一次模型回覆是一個 Step；同一則回覆中的多個工具是一個 batch。模型暫時沒再叫工具，不自動證明任務真的完成。

原始核心：loop、Handle、Limits

Handle

最直接的本地把手。可讀寫 prompt、history、tool results 等公開狀態，也可 pause、resume、end。刻意單純，正確使用由操作者負責。

run()

在目前 thread 一直跑；一個 Handle 只屬於一個 Round、只給一個 runner 使用。

advance()

一次只跑一個 Step 或一整批 tools，抵達 safe boundary 就返回；不在 waiting／paused 卡住。

Limits

附加 callback policy，可限制步數、token、工具等；它是合作式限制，不是 OS sandbox。

背景 thread 是 agentloop.threading.start() 的可選方便工具，不是 worker pool 或 scheduler。

Controller：較舒服的本地用法

Controller 是第一個「C with class」式包裝，不是更高權限的控制平面：它把 bot、初始輸入、Handle 與 runner 樣板收成一個 object，少寫樣板、較容易使用；Handle 仍公開，其他人也可做別種封裝。

c = agentloop.Controller(bot, dispatch, "修好測試"); c.start(); c.handle.pause(); result = c.join()

同一個 Controller 只選逐步、前景或背景其中一種 runner 樣式，避免同一 Handle 被兩個 runner 同時跑。它不是 security boundary，也不負責 persistence、Task queue、revision、Candidate、lease 或 scheduler。

那些「後面才做」的是什麼？

Candidate
模型提出的候選答案或完成宣稱；未來必須和 evidence／verifier 一起判定，不能視為已完成。
durable
程式重啟後仍找得到已知狀態與工作；不是把活的 Handle、callback 或 Python callable 存進資料庫。
scheduler / lease / revision
跨 process worker 的排程與防呆機制。只有需要恢復、多人協調或大量 Round 時，才屬於外圍 service。
SQLite
一種單檔資料庫，未來可作耐久化儲存候選；目前尚未是 agentloop 或 Controller 的需求。

一句話記住

Handle 是原始、直接的本地把手；Controller 是同一層級附近、比較好用的本地封裝；耐久化與調度是更外圍、暫緩決定的服務。

導讀不取代規格。看 agentloop README、Controller、分層記錄。
