INSTRUCTION · EFFECT · RECOVERY

Executor 做事，核心決定算不算數

LLM call、讀寫檔案、執行工具與 Git checkpoint 都是一條 Instruction。差別在成本、可靠度和副作用，不在於誰能繞過提交規則。

一條 Instruction 的生命週期

preparedjournal + fsync
→
leased有期限的執行權
→
dispatched工作可能已送出
→
resultreceipt / unknown
→
committed發布 G+1

最重要的順序是 prepared 落盤後才 dispatch。否則 process 掛掉時，系統無法分辨「根本沒送」和「已送但沒收到回覆」。

可安全重試

驗證失敗、明確 before-send transport error、純讀取或 provider 支援同一 idempotency key 的操作。

不可直接重試

寄信、付款、部署、device write 等可能已成功但 receipt 遺失。狀態進 outcome_unknown，先 reconcile、補償或交給人。

Tool 修改檔案的真實邊界

VFS write

核心先驗證 staged mutation，再發布新 generation；這是可控的正式狀態修改。

Exec workspace

Tool 可把候選輸出寫入 staging，核心再讀 diff/import。但在 Linux sandbox 上線前，它仍可碰絕對路徑或網路，不能稱為隔離。

外部世界

Host filesystem、HTTP、database 和 device effect 保存 intent + receipt/unknown；Git rollback 不會讓它們消失。

Round 與 Step 不混用

單位意思提交邊界
Function可呼叫的程式定義，例如 bot-a版本與 companion 狀態
RoundFunction 的一次完整呼叫可等待、暫停、驗證或終止
Step一次 ask() → messageReply 已提交、tool 尚未 dispatch
Tool batch兩個 Step 之間的工具工作每個 call id 都要有 committed result

模型沒再叫工具，只代表 Round 暫時安靜；不等於 Round terminal，更不等於使用者目標已驗證完成。

共享模型如何安全 unload

  1. Function 到安全邊界沒有 in-flight Instruction、pending tool call 或 writer lease。
  2. Model key 進 draining原子阻止同 endpoint/model 的新 admission。
  3. 等待 active lease 歸零檢查後到 unload 完成前都持有 lifecycle-exclusive lock。
  4. Provider-specific unload只有宣告支援才呼叫；Ollama 用 keep_alive=0 並查 /api/ps。
  5. 載入新模型healthcheck tools/images/context 能力後，才提交 config revision。

Live profile 預設每 Step 4096 output tokens、12 Steps、8 calls、900 秒；測試用 finally unload 最後模型。

Scheduler 真正在平衡什麼

容量與成本

Endpoint slots、RPM/TPM、token、金額、worker、writer lease。

可靠度

能用 deterministic tool 就不先賭 LLM；模型自述 confidence 不能當證據。

人的感受

前景優先、first progress latency、queue age、deadline、pause/cancel 回應。

Function 休眠時只留下 records，不留 parked OS thread。大量 dormant Functions 不等於大量 processes。
