SELF-IMPROVEMENT · EVOMAP REVIEW

改進不是直接改自己

先留下訊號與假設，在 private branch 產生候選版本，用本機證據驗證，最後才讓核心切換 active ref。失敗也要成為可查的結果。

EvoMap 提供的好骨架

GEP 資產白話意思我們怎麼用
Gene可重用策略：何時觸發、怎麼做、限制與驗證Versioned Strategy
Capsule一次真實執行的 diff、環境與結果Improvement Candidate + Evidence
EvolutionEvent成功失敗都追加的稽核事件Append-only Improvement Event

GEP 的七階段是 Detect → Select → Mutate → Hypothesize → Execute → Evaluate → Solidify。最重要的不是名稱，而是「先寫可反駁的預期，後執行，再以結果決定是否固化」。

直接採用的設計

  • Strategy、執行結果、稽核事件分成不同 immutable record。
  • Canonical encoding + SHA-256 content id，用於完整性、去重與 lineage。
  • 先寫 hypothesis；失敗、拒絕、超預算也留下 outcome。
  • 限制檔案／行數／禁止路徑，另記 token、金額、wall time 與 executor revision。
  • 外來資產一律 staging，本機調整並重新驗證，不能直接執行。

刻意不接進核心的東西

Node runtime / Hub

不成為 build dependency。以後若需要，只做有版本的 importer/exporter 或 remote adapter。

遠端品質分數

只影響候選排序，不授予執行權；信心不是安全或正確性證明。

Git hard reset

不是通用 rollback。Git 回不了已發出的 HTTP、信件或金流；外部效果仍走 receipt/reconcile。

自動上傳

預設關閉。Prompt、trace、secret、tool output 與未審 diff 不離開本機；分享必須 opt in。

PR 8 的最小範圍

只用內建 Strategy

先由人 review，凍結 schema；不連 EvoMap Hub。

只升級 versioned ref

Promotion 用 CAS；immutable 歷史與外部效果不被改寫。

只信本機證據

Deterministic verifier、測試、budget 與 effect receipt 是 gate。

若日後相容 GEP

Import 要限制大小與深度、strict schema、重算 hash、檢查來源與 license、移除 validation command 的直接執行權，再轉成內部 Strategy。Export 只從已 promotion revision 產生 allowlisted evidence。

網路來的 Capsule 是不可信資料，不是套件也不是 shell script。Hash 只能偵測內容被改，不能證明作者、授權或安全。
