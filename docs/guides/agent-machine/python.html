REFERENCE IMPLEMENTATION

Python 先把規則說清楚

這版不是一次性 demo。它是日後 C++／Janet 必須通過的 oracle：同一份輸入，應得到相同狀態、錯誤與復原結果。

第一個 PR 不碰模型。 沒有 HTTP、Git、journal、scheduler、FUSE 或 Janet；先把 namespace 的純函數做好。

PR 1：最小資料面

只定四種資料

Node、DirectoryEntry、Operation、Commit。Function、Round、Instruction 留到 executor slice。

只有一個版本軸

v1 使用全 namespace 的 root_generation。兩個 writer 對同一版競爭，必須恰好一個成功。

state_G + Operation(expected=G)
    -> validate(path, pairing, schema)
    -> immutable state_G+1 + Commit

same operation_id  -> same result / duplicate
stale generation   -> conflict

建議檔案

檔案責任
ids.pyNodeId、OperationId，不重用
records.pyFrozen records 與 closed enum
protocol.pyStrict JSON、canonical order、structured error
paths.pyCanonical path、reserved .name、pairing
store.pyImmutable snapshot、pure reducer、root CAS
_checks_*.pyProperties 與 golden vectors

PR 2：真正可以談 crash

  1. 寫 staging/G+1內容、manifest、hash 都完成才往下。
  2. Journal prepared + fsync先留下「正準備發布什麼」。
  3. Atomic HEAD rename發布 G+1，再 fsync parent directory。
  4. Journal committed補完紀錄；清 staging 可以延後。

Kill process 可能發生在每一點。重啟後只能看到完整 G、完整 G+1，或明確的 repair required，不能看到半個 companion directory。

PR 3：Git 是可修復的 checkpoint

Git object寫完 + fresh process 驗證
→
VFS HEAD引用 git_oid
→
managed refCAS 發布，可補做

Git ref conflict 不回滾已提交 VFS。VFS generation 可以是 checkpoint_pending；recovery 驗證 object 後重試 ref publish。
