LOCAL CORE → OUTER SERVICE

先分清現在與未來

FreePy 現在有一個本地 agent core；Agent Machine 則是日後可能建立的耐久化協調服務。兩者不是同一個 package，也不是 Controller 的兩種名字。

看分層看目前程式

目前狀態

可用：llmkit、tooljson、base_tools、agentloop、Handle、Limits、Controller、Pi bridge。

延後：database、scheduler、worker lease、Candidate、Goal/verifier、resource ledger。

由內向外的三段

本地 core

agentloop 管一個 Round：問模型、跑工具、在 safe boundary 暫停。Handle 是直接把手；Controller 是較好用的 wrapper。

入口與函式庫

REPL／GUI／Pi 是互動入口；llmkit、tooljson、read/write/exec 等是基礎能力。它們不自動形成 sandbox。

外圍服務

只有需要跨重啟、多 process、大量 bot 或可靠驗收時，才建立 durable store、scheduler、worker 與 verifier。

一個本地 Round

Stepbot.ask()
→
message提交公開狀態
→
tool batch完整執行
→
next Step帶結果再問

run() 反覆執行；advance() 只跨一個 operation。兩者都使用同一個 owner runner thread。pause/end 等已開始的 operation 完成，才在 safe boundary 生效。

Handle 與 Controller

Handle 公開 prompt、tools、results、callbacks 與控制方法，權力直接。Controller 收好 bot、Handle 與 runner 樣板，提供 advance/run/start/join。它不是 security boundary，也不取代 Handle。

Agent Machine 是什麼

一個未來候選：以可序列化 command/event、transaction store、resource accounting 與 verifier 管理外圍工作。資料邊界仍暫緩，早期 M0 只有 parked prototype。

模型說「完成」只是一個說法。 若未來要可靠完成，需 Goal、evidence 與 verifier；若工具可能已產生副作用但回覆遺失，也不能盲目 retry。
