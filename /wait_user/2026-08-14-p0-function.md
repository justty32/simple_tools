# 一次執行，AOS 要記住什麼？

> 想法草圖 · 約 2 分鐘 · 不回覆也不會卡住

先把 AOS 想成一個幫你叫 Linux 做事、也幫你記住過程的小管家。

例如你人在一個 agent 的資料夾裡，可以這樣交代：

```bash
aos exec ./ask "整理 notes.txt"
```

## 它做了什麼？

1. 記下你交代的事：要叫哪個程式、帶什麼參數、輸入什麼內容。
2. 執行後記下看到的結果：一般輸出、錯誤訊息、以及是否正常結束。
3. 如果剛好在中途斷電或 AOS 被關掉，它會誠實留下「結果不確定」，不會偷偷再做一次可能已做過的事。

這樣的好處很單純：之後不論是人、AOS，還是上層的 agent，都能從檔案知道「當時叫它做什麼」和「目前到底知道多少」。

## 一個三行故事

你說：「整理 notes.txt」。

AOS 開始做，也一路留下執行紀錄。

若中途出事，它停在原地，交由人決定要不要繼續。

## 只問一件事

上面這個方向，對你來說是否自然？回覆「自然」或「不自然」即可。

預設是繼續採用這個方向；你沒空回覆也完全沒關係。
